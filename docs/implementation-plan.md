# 实施与验收计划

本文件配合 [设计分析](design-analysis.md)。已实现 Windows 客户端 MVP，实际完成与验证范围见 [MVP 验证记录](mvp-verification.md)；后续阶段仍为规划。

## 阶段 0：先验证下载链路

在创建复杂界面前，用临时验证工具跑通“解析 → 选择明确轨道 → 下载 → streamcopy 合并 → ffprobe 校验”。只使用用户自有或获授权的样本，不自动读取浏览器会话。

需要覆盖：普通单 P、包含多个 P 的视频、未登录样本、已授权会话样本、一个较长视频。4K／HDR 等以账号和内容实际可用为前提，未验证的能力标为未验证。

记录样本 BV／CID、账号状态类型、引擎版本、可用格式及结果，记录中不包含凭据或媒体签名 URL。用同一 CID 的官方播放器实际可选档位辅助核对，但最终可下载能力以本次取流为准。

完成标准：至少一个单 P 和一个多 P 样本完成下载与合并；明确知道现用引擎的权限、格式和失败边界。如果拿不到预期格式，先解决解析与授权，不用界面掩盖问题。

## 阶段 1：Windows 独立客户端 MVP

技术栈确定为 Electron + React + TypeScript + Python。先建立 main／preload／renderer 边界和共享协议，再接入阶段 0 已验证的下载引擎；React 通过受控 IPC 与主进程通信，主进程通过 JSONL 管理 Python worker。

交付功能：

- 输入 BV、完整视频链接、带分 P 链接及 b23.tv 短链接。
- 用户主动导入 B 站 Cookie 文件，并能验证及清除应用保存的会话。
- 显示实际视频／音频轨道，明确选择分 P；支持“最高可用画质”和“兼容优先”。
- 单任务下载、取消、无重编码合并、ffprobe 校验、打开目录。
- 显示解析、下载、合并、校验阶段，错误对应具体操作建议。
- Electron 完整发布目录或 NSIS 安装包，包含 PyInstaller onedir 引擎与媒体工具，不依赖开发者机器的 Python、Node.js、.NET 或 PATH。

暂不纳入：插件、二维码登录、收藏夹／UP 主全量下载、自动订阅、直播录制、云端服务、烧录字幕、重新编码、DRM 内容。

完成标准：普通用户双击启动，在完整清空开发依赖的验证环境中完成一次授权样本下载；结果包含正确视频和音轨，格式选择与结果一致，未静默降级。

## 阶段 2：持久队列与恢复

增加 SQLite、任务串行队列、暂停／恢复、有限重试、崩溃恢复、冲突文件处理、磁盘空间检查与诊断导出。

完成标准：

- 下载中关闭进程后，重新启动显示已中断任务，能检查并恢复。
- 地址刷新后不会误把不同格式的片段拼接。
- 合并失败仍保留已完成轨道，可以重试合并。
- 磁盘不足、目录无权限、文件重名、Unicode 标题及长路径均有明确结果。
- 退出应用不会留下继续占网或占用文件的下载／ffmpeg 孤儿进程。

## 阶段 3：Chrome／Edge 一键插件

实现页面视频识别、当前 P、发送到客户端、连接状态和重复点击去重。Native Messaging 主机通过当前用户命名管道连接客户端；客户端对任务明确接收后，插件才显示成功。

用户主动授权时可增加 B 站 Cookie 传递。只申请实际使用的站点和扩展权限，不申请全部网站 Cookie。安装／卸载验证主机注册及残留清理。

完成标准：浏览器页面切换分 P 后识别正确；页面关闭或浏览器退出不影响客户端已接管的任务；不匹配的扩展 ID、非法消息及任意本地命令被拒绝；凭据不会传给网页内容脚本。

## 阶段 4：体验增强

按实际需求加入二维码授权、外置字幕／封面／弹幕、结果元数据、经过验证的 HDR／高级音频、引擎独立更新。

跨平台需求明确后，沿用 Electron／React 界面，分别适配 Python 构建、ffmpeg 资源、凭据存储和安装包；不以 Windows 成功代替其他系统验收。

## 关键验收场景

1. **原画质语义**：下载前显示所选编码、尺寸、帧率；媒体合并路径不使用编码器，不擅自缩放或处理画面。样本校验可比较合并前后解复用的媒体数据，不能仅凭整个容器 SHA-256 判断。
2. **权限不足**：会话无效或目标档位不可用时停止并解释，不把低画质下载成“高清成功”。
3. **多 P 正确性**：默认仅下载链接指定 P，多选时每 P 独立命名、选格式和记录结果。
4. **轨道完整性**：除本身无音频的内容外，不能把只有画面的文件标记为成功；检查预期轨道和时长。小幅时长差需有合理容差。
5. **中断恢复**：在视频下载、音频下载和合并阶段分别终止进程，验证恢复策略与文件保留。
6. **地址过期／拒绝访问**：模拟过期和 403，验证有限刷新、会话失效提示和不静默换格式。
7. **限流**：429 触发退避，不产生持续快速重试；手动取消能停止等待及后续请求。
8. **凭据边界**：检查日志、SQLite、成品元数据、错误消息和诊断包，无明文 Cookie 或完整签名 URL。
9. **发布可运行**：干净的 Windows x64 环境不手工装 Python、不依赖系统 ffmpeg 即可使用；第三方许可随包提供。
10. **高级格式不误报**：HDR／杜比／高分辨率分别实测；不具备样本或设备时标记未验证，不用普通 SDR 成功代替高级格式验收。
11. **Electron 边界**：renderer 不具备 Node 能力，preload 无任意 IPC／命令入口；非法来源和参数被主进程拒绝，进度订阅可以注销，重载窗口不会重复创建下载。
12. **打包与进程**：在中文及空格路径安装后能启动引擎；ASAR 外资源定位正确，退出／取消能清理 Python 与 ffmpeg 子树，配置不写入安装目录。

## 建议的未来代码布局

当前代码按以下布局组织；`extension`、`native-host` 尚未实现：

```text
bilibili-download-vido/
  desktop/
    src/main/              Electron 主进程、任务管理、凭据与本地存储
    src/preload/           contextBridge 与受控 IPC
    src/renderer/          React + TypeScript 界面
    src/shared/            协议类型与共享定义
  engine/                  Python worker 与 BilibiliProvider
  extension/               Chrome／Edge MV3 扩展
  native-host/             Native Messaging 到命名管道的桥接
  packaging/               依赖锁定、许可清单及发布脚本
  tests/                   格式策略、协议、恢复与脱敏验证
  docs/                    设计、验证记录及用户说明
```

优先实现阶段 0，再完成客户端 MVP；插件以同一套任务模型复用客户端能力。
